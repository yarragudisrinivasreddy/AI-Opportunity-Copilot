# Architecture

```
Browser (React, Firebase Hosting)
   | HTTPS, Firebase ID token (anonymous auth), /api/** rewrite
   v
Cloud Run: FastAPI  ------------------------------+
   |  api/routes.py (thin)                         |
   |  services/cases.py (workflow, ownership, gating)
   |        |                                      |
   |   core/privacy.py --> Cloud Vision (faces), Cloud DLP (image PII)
   |        |                       sanitised frames only
   |   agents/*  --> llm/client.py Protocol --> Vertex AI Gemini (structured output)
   |   core/* deterministic: rubric, roi, scoring, injection, text_pii
   |        |
   +--> repo/*  Firestore (cases + subcollections)   Cloud Storage (sanitised frames)
        Secret Manager (any API secrets)
```

## Request flow

1. `POST /cases` creates a case (daily cap check). 2. `POST /cases/{id}/media` validates by magic bytes, samples video frames, **sanitises each frame**, stores sanitised JPEGs. 3. `POST /analyze` runs Agent 1 on sanitised frames and/or the cleaned description. 4. User confirms/edits; answers need-driven questions. 5. `POST /discover` runs Agent 2; code derives recommendations. 6. `POST /brief` runs Agent 3; code adds ROI ranges, status and disclaimer. 7. `POST /proposals/seed` attaches simulated proposals. 8. `POST /evaluate`: per-proposal injection scan and isolated extraction, **code scoring and ranking**, rationale with verified citations (template fallback).

State machine: `captured -> analyzed -> confirmed -> discovered -> briefed -> proposals -> evaluated`. Out-of-order calls return 409.

## Module map

| Path | Responsibility |
|---|---|
| `app/config.py` | Env settings; refuses unsafe production config |
| `app/security.py` | Auth (Firebase or dev header), rate limiter, security headers middleware |
| `app/core/rubric.py` | Enum rubric to strength and recommendation |
| `app/core/roi.py` | Parse volume/time; effort ranges with assumption text |
| `app/core/scoring.py` | Five criteria, weights, tie-break, inferred-context flags |
| `app/core/injection.py` | Normalise, pattern scan, strip instruction-like segments |
| `app/core/privacy.py` | Validate, blur faces, mask PII, strip EXIF, sample video; GCP detectors |
| `app/core/local_privacy.py` | Dev/test detectors (OpenCV Haar, static boxes) |
| `app/agents/*` | Four agents + deterministic question selection |
| `app/llm/*` | `LLMClient` Protocol, `structured_call` retry helper, Vertex client, fake, prompts |
| `app/repo/*` | `Repository`/`MediaStore` Protocols; in-memory and GCP implementations |
| `app/fixtures/*` | Sample case, simulated providers/proposals (generated by `scripts/build_fixtures.py`) |
| `eval/*` | Metrics and benchmark runner |

## Why these choices

- **Protocols everywhere** so every external service is replaceable and the whole suite runs offline.
- **LLM for interpretation, code for decisions** makes outputs reproducible, testable and resistant to injection.
- **Deny-all Firestore rules** because the browser never reads Firestore.
